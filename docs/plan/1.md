 Auto-Fix Pipeline: Implementation Plan

 Context

 Problem: Production errors detected in Elasticsearch require manual triage — fetch logs, diagnose, fix code, write
 tests, create PR. This cycle repeats for every error and is slow, manual, and inconsistent.

 Goal: Build an opensre auto-fix subsystem that automates the entire fix-test-PR cycle. Hourly ES error scan → Claude
 Code CLI fixes the bug → generates unit + integration tests → loops until tests pass → creates a GitHub PR — all
 autonomously.

 Target repo: https://github.com/woyao-cloud/ollama-03-02-claude-prompt02-template.git (cloned locally)

 Data Flow

 CLI: opensre auto-fix run
   │
   ├─ 1. ErrorFetcher.fetch_new_errors()
   │     └─ ElasticsearchClient.search_logs() → filter errors → dedup vs state
   │
   ├─ 2. For each new error (sequential, 1 per cycle):
   │     ├─ ContextLoader.load_context(error)
   │     │   └─ git log, extract file refs from traceback, read file contents
   │     │
   │     ├─ FixEngine retry loop (max 3):
   │     │   ├─ GitOps.pull_main() + create_fix_branch()
   │     │   ├─ PromptBuilder.build_fix_prompt() → CLIBackedLLMClient(ClaudeCodeAdapter)
   │     │   │   └─ Claude Code modifies files in repo
   │     │   ├─ PromptBuilder.build_unit_test_prompt() → Claude Code → run tests
   │     │   ├─ PromptBuilder.build_integration_test_prompt() → Claude Code → run tests
   │     │   └─ Tests passed? → break / retry (reset branch)
   │     │
   │     ├─ GitOps.commit() + push()
   │     └─ PRCreator.create_pr() via GitHub MCP
   │
   └─ State update → COMPLETED / FAILED / SKIPPED

 State Machine

 NEW → FETCHING → FIXING → TESTING_UNIT → TESTING_INTEGRATION → PR_CREATION → COMPLETED
                                                   ↓ (fail, retry < max)
                                                FIXING ← pull main, new branch
                                                   ↓ (fail, retry == max)
                                                FAILED

 NEW → SKIPPED (deduplicated)
 PR_CREATION → FAILED (if MCP error)

 CLI Design

 opensre auto-fix run          # One cycle (immediate, foreground)
 opensre auto-fix start        # Daemon mode (background, hourly)
 opensre auto-fix stop         # Stop daemon (read PID, SIGTERM)
 opensre auto-fix status       # Show state summary (Rich table)
 opensre auto-fix log          # Show recent activity

 5. Register in app/cli/commands/__init__.py

 Phase 2: Core Logic

 8. context_loader.py — git log + file reading (uses subprocess git + Path.read_text)
 9. prompts.py — Three prompt template methods
 10. git_ops.py — Pull, branch, diff, commit, push (uses subprocess git)
 11. Tests for each

 Phase 3: Engine + PR + Daemon

 12. pr_creator.py — Uses github_mcp_config_from_env() + call_github_mcp_tool()
 13. fix_engine.py — FixEngine.run_cycle() with retry loop (the state machine)

 15. Wire full CLI with Rich output for status and log
 16. Tests with mocked Claude, ES, git

 18. make lint, make typecheck, make test-cov
