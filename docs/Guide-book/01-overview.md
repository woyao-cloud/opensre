# OpenSRE 解决什么问题，核心原理是什么

## OpenSRE 解决什么问题

生产事故调查的难点通常不在“缺少一个模型”，而在以下几点同时存在：

- 线索分散在多个系统里：日志、指标、链路追踪、监控平台、云平台、CI/CD、工单系统、聊天工具
- 每个系统的认证方式、API 风格和查询语义都不一样
- 调查过程本身是一个多步骤流程，而不是单轮问答
- 调查过程中需要保留上下文、做回环、控制预算、避免重复动作
- 最终输出不仅要有“答案”，还要有证据、可回溯链路和可投递报告

OpenSRE 的目标是把这件事程序化：  
把一条原本靠人工在多个控制台之间跳转完成的 RCA 流程，变成一条可编排、可扩展、可追踪、可测试的 Agent 执行链。

## 一句话理解 OpenSRE

OpenSRE 本质上是：

> 一个以 LangGraph 为编排内核、以统一状态模型为上下文载体、以工具和集成为能力接口、以 service 层封装外部系统访问的 AI SRE Agent 框架。

## 核心实现原理

它的实现思路可以压缩成 6 步：

1. 接收告警或交互输入。
2. 把输入规整成统一的调查状态。
3. 通过图执行节点抽取关键信息并解析可用数据源。
4. 基于数据源和上下文规划下一批调查动作。
5. 并发执行工具、汇总证据、做根因诊断，必要时回环继续调查。
6. 生成最终报告，并推送到外部通道。

其中最关键的不是 LLM 本身，而是三层解耦：

- `integrations` 负责把第三方系统接进来
- `tools` 负责把“可执行动作”暴露出来
- `services` 负责真正和外部 API、LLM、远程运行时通信

因此，LLM 在 OpenSRE 里扮演的是“受控推理组件”，不是“包打天下的黑盒主程序”。

## 系统分层

从代码结构看，OpenSRE 可以分成五层。

### 1. 入口层

负责接收输入和输出结果：

- `app/cli/`
- `app/entrypoints/`
- `app/main.py`
- `app/webapp.py`
- `app/remote/server.py`

### 2. 编排层

负责定义执行顺序和控制流：

- `app/pipeline/`
- `app/nodes/`

### 3. 状态层

负责在不同节点之间传递统一上下文：

- `app/state/`
- `app/types/`

### 4. 能力层

负责连接外部系统并执行调查动作：

- `app/integrations/`
- `app/tools/`
- `app/services/`

### 5. 横切层

负责认证、安全、可观测性和运维控制：

- `app/auth/`
- `app/guardrails/`
- `app/masking/`
- `app/sandbox/`
- `app/analytics/`
- `app/utils/`

## 模块构成总览

### `pipeline`

定义统一执行图、路由逻辑和本地 runner。

### `nodes`

定义具体节点，例如：

- 抽取告警
- 解析集成
- 规划动作
- 执行动作
- 归并结果
- 根因诊断
- 报告发布

### `integrations`

定义第三方系统如何被标准化接入系统，包括：

- 配置模型
- 存储格式
- 注册表
- 环境变量加载
- 验证探针
- 多实例选择

### `tools`

定义 Agent 可以执行的具体动作。  
例如查询 Grafana Loki、Datadog logs、GitHub commits、S3 对象、RabbitMQ 队列、Vercel 部署状态等。

### `services`

提供更底层的供应商客户端和 LLM 访问抽象。  
工具一般不直接手写 HTTP 逻辑，而是调用 service client。

### `cli`

是 OpenSRE 最重的外层模块之一，包含：

- 顶层命令
- investigate 命令
- onboarding 向导
- interactive shell
- doctor / health / deploy / integrations 等子命令

## 为什么需要这么多层

如果没有这些层，系统很快会退化成几类常见坏味道：

- 供应商 API 调用散落在各个节点中
- 告警抽取、规划、执行和诊断互相耦合
- 工具无法统一注册，无法做 surface 区分
- 本地运行和远程运行各写一套
- 认证、护栏和脱敏只能靠调用方自觉处理

OpenSRE 通过模块化设计避免了这些问题：

- 节点只做编排，不做重型供应商接入
- 集成只做标准化，不直接承担全部调查逻辑
- service 只做“访问外部能力”，不做编排
- tool 只暴露“一个统一动作面”，不管谁调用它

## 阅读这套代码时应抓住的主线

如果只抓一条主线，应该是：

`入口 -> 初始状态 -> 图执行 -> 节点编排 -> 数据源检测 -> 工具执行 -> 证据汇总 -> 根因诊断 -> 报告发布`

后面各章都会围绕这条主线展开。
